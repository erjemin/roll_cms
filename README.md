## Шаблоны

RollCMS задумана как CMS которой можно управлять через шаблоны (за исключением какого-нибудь совсем специфического функционала).

**Шаблон** - это файл, который содержит разметку страницы, и в который вставляется контент. Контент вставляется в шаблон в определенные места, которые называются **переменными контекста** или **контекст-переменными**.

**Для корневой страницы `/` используется шаблон `index.jinja2` или `index.html`** (приоритет у шаблонов jinja2).

В RollCMS шаблоны хранятся в базе данных, и их можно создавать и редактировать через админку. Тем не менее, все шаблоны созданные и редактируемые через админку так же записываются в файловую систему.

Так же шаблоны можно создавать и редактировать и в файловой системе.  Но нужно соблюдать определенные правила:

1. Шаблон в файловой системе имеет приоритет при редактировании через админку (только при редактировании). Т.е. если шаблон существует и в фаловой системе, и в базе, то при редактировании через админку будет загружен шаблон из файловой системы. При сохранении шаблона, он будет сохранен в файловую систему, и в базу данных.

2. Если шаблон создан в файловой системе, он будет автоматически записан в базу данных __первом вызове на рендер__ (такой механизм задуман для дистрибуции готовых сайтов вместе с RollCMS). Но до __вызова на рендер__ его в базе не существует, а значит и в админке не отображаться. Это означает, что нужно быть внимательным, так как можно _случайно перезаписать_ шаблон в файловой системе, попытавшись создать шаблон с тем же именем через админку. Чтобы получить шаблон из файловой системы при первичном описании в админке, достаточно оставить поле "Код шаблона" пустым и при записи (кнопки "Сохранить...") шаблон из файловой системы будет записан в базу данных. 

3. Если уже существующий в файловой системе шаблон отредактирован через файловую систему, то такие изменения не попадут в базу данных. При работе RollCMS, такие изменения шаблона не будет отображаться на сайте, а будет отрабатывать старый шаблон из базы. Чтобы "синхронизировать" шаблон из файловой системы с базой данных, нужно "отредактировать" шаблон через админку. Достаточно просто открыть шаблон на редактирование (при этом в поле "Код шаблона" попадет уже шаблон из файловой системы, и нажать "Сохранить...". 
 
Поддерживаются шаблоны Django и Jinja2. Через файловую систему шаблоны следует  располагать в каталог `templates-django` и `templates-jinja2` соответственно (названия каталогов можно изменить через `setting.py`). При создании шаблона через админу, если у шаблона указаны расширения `.jinja2`/`.j2`/`.jinja`, то он будет сохранен в каталог `templates-jinja2` и будет обработан как jinja2-шаблон. Любое другое расширение будет считаться шаблоном Django, в будет помещено в каталог `templates-django`. 
Рекомендуемое расширение для шаблонов Django - `.htm`/`.html`.

### Подкаталоги для шаблонов

Какой шаблон использовать для отображения страницы в RollCMS определяется через URL страницы (см. раздел "URL и их обработка"). Через URL определяется и какой контент будет загружен в шаблон. 

Но шаблоны Django и Jinja2 поддерживают вложенность. Можно как вставить один шаблон в другой:
```jinja
{% include "blocks/accept-cookies.jinja2" %}
``` 

Так и указать шаблон-родитель, и в нем определить блоки, которые будут переопределены в дочерних шаблонах. Например в шаблоне:
```jinja
{% extends 'base.jinja2' %}{# <---- указание подключить шаблон-родитель #}

{% block title %}{{ title }}{% endblock %}
{% block content %}{{ content }}{% endblock %}
```

А в шаблоне-родителе `base.jinja2`:
```jinja
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>САЙТ: {% block title %}{% endblock %}</title>
</head>
<body>
  {% include "menu/main-menu.jinja2" %}
  <div id="content">{% block content %}{% endblock %}</div>
</body>
```

Вставленный шаблон, может содержать и свои вложенные, и шаблоны-родители, шаблон-родитель тоже может содержать свои родительские шаблоны и другие встроенные шаблоны. Таким образом выстроится цепочка подключенных шаблонов. И все эти шаблону будут вызваны по одному URL, при обращении к сайту. Такая же ситуация и с корневым шаблонами `index.jinja2` и `index.htm`. т.к. у URL корой страницы URL пустой и невозможно определить какой контент подключить.

Чтобы понять, какой контент подключить в такие шаблоны, RollCMS использует следующие соглашения по размещению шаблонов внутри каталогов `templates-django` и `templates-jinja2`.

* **menu/** -- шаблоны навигационных меню. В такой шаблон будет подгружаться контент из меню и пунктов меню сейта.
* **roll/** -- шаблоны роллов. В такой шаблон будет подгружаться списки роллов (например лента новостей, блогов, блок слайд-шоу и тому подобное) из страниц.
* **item/** -- шаблоны элементов. В такой шаблон будет подгружаться контент из элементов страницы (например, текст новости).
* **cash/** -- кэш-шаблон (такой кеш-шаблон может создаваться автоматически для ускорения работы, и пока такой механизм есть только для блоков меню. т.к. навигационный блок меню меню). Предполагается, что кэш-шаблон -- это чистый html, и контекстные-переменные в него не передаются (и даже если их передать, они не обработаются).

## Roll-переменные которые могут передаваться с любым контекстом

Совместно с некоторым контекстом в шаблоны могут передаваться скрытые системные ролл-переменные. Все скрытые ролл-переменные начинаются с префикса `__` и пишутся заглавными (прописными) буквами, так что просто старайтесь не использовать для передачи контекста в шаблон переменные начинающиеся с `__` и из заглавных букв, и всё будет хорошо.

### URL-префиксы

Т.к. в `settings.py` можно задать URL-префикс для роллов, элементов и шаблонов, то некоторым видам шаблонов нужно знать их. URL-префиксы передаются в шаблоны через следующие переменные:

* `__URL_PREFIX_ROLL` -- URL-префикс для роллов
* `__URL_PREFIX_ITEM` -- URL-префикс для элементов
* `__URL_PREFIX_TAGG` -- URL-префикс для тегов

Так же некоторым шаблонам нужно знать полный путь того, что сейчас отображается (для формирования абсолютных ссылок) и цепочку "Хлебных крошек". Эти переменные передаются в шаблоны через следующие переменные:

* `__URL_CHAIN` -- Полный путь отображаемого контента
* `__BREADCRUMBS` -- Цепочка "Хлебных крошек" (список кортежей вида `[(url, title), ...]`)

Для отладки иногда нужно посмотреть весь контекст передувающийся в шаблон. Для этого можно использовать переменную:

* `____ALL_ROLLCMS_CONTEXT` -- Весь контекст передаваемый в шаблон
 
## Объявления переменных внутри шаблонов

Как принято в Django, RollCMS передает в шаблон контекст, который содержит переменные, которые можно использовать в шаблоне. Переменные контекста могут быть объявлены в самом шаблоне, во вложенных шаблонах, в шаблоне-родителе, в шаблоне-родителе-родителя и т.д. О том какие переменные передаются в контексте, будет описано в разделе "Контекстные переменные".

Помимо контекстных переменных в RollCMS можно объявлять **ролл-переменные** (пока не придумал другого названия). Эти переменные объявляются внутри комментариев jinja2- и django-шаблонов: `{# RollCMS_имя_переменно значение #}`. Такие конструкции будут восприниматься самими Django как комментарии, но предварительно будут обработаны RollCMS.

> Ролл-переменные не обязательны, но могут быть полезны при встраивании одних шаблонов, в другие. 

Дело в том, что шаблона может использовать только контекст переданный ему. Контекст RollCMS получает на основе URL странички. по которому обратились к сайту. Но когда шаблон встраивается в другой шаблон, то может или вовсе не получить необходимого контекста, или ему понадобится контекст с характеристиками несколько отличными от базовых для этого шаблона. Например, у нас есть лента новостей, есть шаблон отображающий эту ленту и характеристики этой новостной ленты: сколько элементов информации на одной странице (например -- десять). Все это будет отображаться на странице "Новости" по ссылке `/news`. Но если мы хотим встроить эту ленту в другую страницу, например на главную, то нам, возможно, понадобится выводить только три новости, а не десять. Чтобы задать этот параметр (только три новости), можно использовать ролл-переменные.

Пример объявления ролл-переменной:
```jinja
{# RollCMS_ItemIn 3 #}
```

### Ролл-переменные общие для всех шаблонов

Как сказано выше, шаблоны в RollCMS находятся и в файловой системе, и в базе. При первом запуске (или при дистрибуции RollCMS как готового сайта) может так случится, что шаблон уже есть как файл, но еще отсутсвует в базе данных. В таком случае, при первом обращении к сайту, шаблон будет загружен из файловой системы, и в базу данных. Но в базе данных для каждого шаблона есть своя переменная для передачи контекста, и техническое описание шаблона. Переменные для передачи контекста и его техническое название могут быть объявлены в самом шаблоне.

#### RollCMS_var -- переменные для передачи контекста

```jinja
{# RollCMS_var top_menu #}
```

#### RollCMS_description -- техническое описание шаблона

```jinja
{# RollCMS_description Шаблон-для-вывода-верхнего-меню-сайта #}
```

### Ролл-переменные для шаблонов роллов

#### RollCMS_RollItemIn -- количество элементов в ролле

```jinja
{# RollCMS_RollItemIn 3 #}
```

#### RollCMS_RollFilterRule -- правило фильтрации элементов ролла

В ролл, например ленту новостей, можно встроить правило фильтрации информационных элементов в ролле. Например,
показывать только новости за последний месяц. Правила фильтрации в RollCMS задаются так же
[как в ORM Django](https://docs.djangoproject.com/en/5.0/ref/models/querysets/#field-lookups) (в виде строки
без пробелов).

Например, все опубликованные информационные элементы:
```jinja
{# RollCMS_RollFilterRule bPublish=True #}
```

Или, элементы у которых есть картинки-превью:
```jinja
{# RollCMS_RollFilterRule bPublish=True,kImg__isnull=False #}
```

#### RollCMS_RollSortRule -- правило сортировки (order_by) элементов ролла

Правило сортировки элементов ролла задается так же, [как
и в Django ORM](https://docs.djangoproject.com/en/5.0/ref/models/querysets/#order-by).

Например, сортировка по дате публикации (в обратно-хронологическом порядке):
```jinja
{# RollCMS_RollSortRule -tdStart #}
```

Или по специальному полю сортировки:
```jinja
{# RollCMS_RollSortRule iSort #}
```

Или сортировка по числу просмотров (в порядке убывания):
```jinja
{# RollCMS_RollSortRule -iCount #}
```

Если нужно сортировать по нескольким полям, то, например:
```jinja
{# RollCMS_RollSortRule -iCount,-tdStart #}
```
Т.о. получим ролл отсортированный по числу просмотров (по убыванию), а затем, в случае равенства числа
просмотров, по дате публикации (обратно-хронологически).

"Сортировка" в случайном порядке может создать значительную нагрузку на базу-данных, тем не менее её
тоже можно сделать:
```jinja
{# RollCMS_RollSortRule ? #}
```
